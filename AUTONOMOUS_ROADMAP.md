# Autonomous pixel art production

Implementation status: foundation started. Managed production approval is deliberately unavailable until artifact verification and isolated host review adapters exist.

## Accepted architecture

Use the host agent for visual reasoning, with separate author, artistic reviewer and contextual reviewer contexts. Cover all 2D pixel art. Export a universal manifest and validate exported artifacts through a reference simulator. Keep basic rendering compatible. Allow per-project art direction and verified extensions. Stop at configured budgets without approving deficient work.

## Implementation sequence and acceptance gates

1. **P0 — Capability contracts:** consolidate operation metadata, reject unknown managed fields, report inactive parameters, test installed distributions, and separate style metrics from artistic judgment. Empty artwork must never pass style comparison. Status: empty artwork guard, wheel/sdist resources, explicit generator field help/lint, nested managed field validation and fresh checks after imports implemented. Inactive-parameter reporting and full parameter type/range contracts remain pending.
2. **P1 — Semantic design:** version ProjectBrief, ArtDirection, AssetSpec v2, AssetManifest v1, Review v2, WorkflowTask, ReleaseManifest and ExtensionManifest. Track stable part IDs, materials, structure, anchors and dependencies through transforms. Preserve original-canvas coordinates and explicit atlas offsets. Status: initial named assembly graph supports parent-relative translation, validated ids/parents, draw order and transform-aware part origins. Full semantic constraints and versioned contracts remain pending.
3. **P2 — Persistent director:** transactional task scheduling, idempotent next/start, resume, evidence submission, revision tracking, dependency invalidation, budgets and cycle detection. Status: SQLite queue, ordered stage-specific submissions, archived hash-bound evidence, downstream/brief invalidation, audit events, review-triggered construction repairs, revision/review budgets and repeated-defect strategy changes implemented. Complete revision modeling remains pending.
4. **P3 — Visual evidence:** host adapters record separate reviewer contexts and viewed artifact hashes. Require localized observations at native resolution and integer zoom. Each applicable criterion needs both reviewers to score at least 3/4. Missing or conflicting evidence blocks release. Status: role-specific native/4x packets, complete-view evidence coverage and declared context separation are implemented. Trusted host observation/isolation adapters remain pending.
5. **P4 — Structural search:** six silhouette proposals, at most two developed candidates, whole-asset and per-part catalog comparisons. Normalize translation and padding. Separate legitimate variants from accidental duplication. Reject defects by revision and cause, permitting verified repairs. Status: six source-verified native PNG proposals with distinct descriptions and rendered content are required; pairwise silhouette diagnostics are recorded. Meaningful visual diversity, part-level catalog integration and repair-aware legacy rejection remain pending.
6. **P5 — Generators:** morphology and posture graphs for characters; growth graphs for trunks and roots; building footprints and connected roof volumes; fracture-driven rocks and directional materials; compositional UI ornament grammars and nine-slice contracts. Require visible differences without recoloring or decoration. Status: six broadleaf growth architectures, seven top-down human body plans, six connected building layouts, six fractured rock mass profiles and six UI composition layouts provide inspectable graphs and proposal comparisons. Human equipment stays rigid and fitted; trees/buildings/rocks can be reviewed without ornament or deposits. Rock half-plane cuts drive actual facets with conserved area; ore follows faults/junctions and moss follows exposure planes. Architecture has rotated footprint/ridge graphs and depth-tested faces. UI reserves content and sparse fixed-cap ornament, with source-bound nine-slice/state checks. Complete acting, species/growth/harvest behavior, richer architecture, general directional materials, UI text/layout integration and commercial visual validation remain pending.
7. **P6 — Acting:** explicit key poses, variable durations, anticipation, contact, recovery, secondary motion and expressive profiles. Track root motion, planted feet, events and interruption transitions. Intentional holds are valid. Status: declared planted sockets have bounded per-millisecond world-space drift monitoring. Versioned animation scores validate complete beat coverage and timed gameplay events, with source-bound export, contract-required names and bounded loop/interruption traces. Bounded lean/crouch controls support authored body loading while preserving ground-line feet, head mass and rigid equipment. The strike example exercises these controls. Sequence diagnostics separate root travel, body posing and limb-only transitions, including holds/loop joins; review packets recompute them from verified sources. These signals do not establish acting quality. Joint-constrained posing, automatic contact intent, expressive profiles and secondary motion remain pending.
8. **P7 — Full 2D coverage:** functional item parts and states, portrait landmarks and expressions, background composition and depth, illustration focal hierarchy, VFX phases and parallax. Category-specific requirements prevent inappropriate gameplay checks. UI composition provides six content/chrome layouts, sparse corner motifs, six explicit states and source-bound nine-slice evidence. Managed delivery requirements enforce stable geometry, native/resized content capacity and requested visible state distinctions. Text/layout integration and full category coverage remain pending.
9. **P8 — Exported-artifact simulator:** consume only universal manifests and exported pixels. Verify pivots, collisions, sorting, directions, transitions, background readability, relative scale, gameplay states, legal Wang/Blob adjacency, spatial seams and temporal loops. Emit machine traces and visual evidence. Status: exported playback, pivot placement, Y sorting, convex-region overlap, protected state changes, delivery coverage and Wang16 comparison sheets are implemented. Explicit architecture footprint derivation preserves connected-mass gaps in exported collision regions, with source-bound entrance anchors. 10. **P9 — Repair and extension:** localized repair tasks with hypotheses and expected outcomes. Prefer metadata, parts and alternative structures before reusable extensions. Require real host isolation, tests, pinned hashes and rollback; a virtual environment alone is insufficient. Pending.
11. **P10 — Catalog release:** verify coverage, diversity and project consistency. Recheck current hashes and reviews. Publish complete local bundles atomically with sources, manifests, previews and verification reports. Pending.

## Budgets and approval

Default per asset: six structural proposals, two developed candidates, 36 rendered revisions, 24 visual review tasks, two extension attempts. Three unsuccessful corrections of the same defect require a strategy change. Exhaustion retains provisional candidates and blocks approval. Task submissions alone must never produce production approval.

## Verification

Maintain engineering tests for schema validation, transform metadata, deterministic rendering, timings, events, resume, stale reviews, atomic releases and installed-package execution. Include adversarial cases: empty art, ignored parameters, one-pixel changes, recolors, padding, valid silhouette-preserving repair, intentional holds and particles.

Create 120 benchmark briefs across twelve categories, eight development and two reserved briefs per category; run each three times. Target zero approvals with known contract failures, all deterministic seeded defects detected, at least 95% seeded visual defect detection, at most 5% false rejection and at least 90% reserved task completion within budget. Report category results separately.

Final demonstration: an interactive village with two distinct characters, four trees, three buildings, three rocks/resources, six objects, five UI components, a tileset, two portraits, a background and two effects. Exercise movement, direction changes, occlusion, interaction, harvesting, damage and UI. Reference-simulator verification does not imply verification in a specific engine.

## Experimental commands

`pixelai project init DIRECTORY --brief brief.json` requires a nonempty `goal`.

`pixelai workflow start|next|status|resume PROJECT --json` exposes the persistent queue. `pixelai workflow submit PROJECT --task ID --input response.json` requires an evidence array of project-relative file records such as `{"path":"art/sprite.png"}`. Files are hash-bound and rechecked; changed evidence invalidates dependent tasks. Stage-specific output requirements are returned by `next`. Declared review identities are checked for conflicts but not authenticated by a host adapter. Completing the queue returns `blocked`, never `approved`.

`pixelai simulate asset.manifest.json --json` validates texture hashes, frame regions, nonempty exported content, coordinate finiteness, clip references and variable durations; it produces a deterministic timing trace. Physics, sorting behavior, seams and visual quality remain unverified.

`pixelai diversity first.png second.png --json` compares normalized silhouettes, including reflection. Similarity is a review signal, not an originality verdict. Compare separate native assets rather than entire atlases.

Project briefs may set `budgets.rendered_revisions` and `budgets.visual_reviews`. A criterion below 3 in either review reopens construction, retains the failed review in the audit log and preserves spent budget. Default limits are 36 construction submissions and 24 visual review submissions. These count submissions, not every renderer call outside the managed workflow.
